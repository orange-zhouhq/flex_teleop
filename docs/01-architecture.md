## 七个环节

| # | 环节 | 频率 | 产出 TARGET | 维护 STATE |
|---|---|---|---|---|
| ① | VR 采集 | 30Hz | `VrPose`（OpenXR 原始） | 跟踪有效性、id 计数器 |
| ② | 坐标变换 | 30Hz | `PoseFrame`（基座系） | 标定锚点、重定位、身高/坐站 |
| ③ | 下行传输 | 30Hz | 整帧自描述报文 | 接收缓冲、丢帧计数、看门狗 |
| ④ | 帧对齐 + 插值 | 200Hz | 插值目标 `(id_a, id_b, α)` | 双缓存、α、无新帧计数 |
| ⑤ | QP IK | 200Hz | `q_cmd[7]` | `q_prev`、φ、branch、solve_state |
| ⑥ | 关节流式目标 | 200Hz | `JointStream` | tick_seq、模式、仲裁 |
| ⑦ | Ruckig OTG + 伺服 | 1kHz | 1kHz 平滑轨迹 → 位置环 | `(q, qd, qdd)`、v/a/j 约束、`q_fb` |

**关键**：①–② 在同一进程；④–⑥ 在同一 200Hz 循环；⑦ 在驱动器侧。跨进程边界只有 ③ 和 ⑦ 的反馈，其余都是内存传递。

---

## 两个入口

```
VR pose 30Hz ──▶ ① ② ③ ④ ⑤ ──┐
                                ├──▶ ⑥ 关节流式目标 200Hz ──▶ ⑦
上层关节 30Hz ──────────────────┘
                                  （旁路 ⑤）
```

- **pose 模式**：走完整链路，IK 求解
- **joint 模式**：上层直接给关节目标，跳过 ④⑤
- 仲裁规则：按最近一帧生效；模式切换时 `pose_id` 必须连续，不允许断档

这条旁路是有意的设计——示教器、回放、脚本轨迹都可以复用同一条 200Hz 流，而不必伪造位姿。

---

## 三条时基

```
30Hz ─────────────▶ 200Hz ─────────────▶ 1kHz
pose_id              tick_seq             无 id
（跨机器）            （单机）              （本地闭环细节）
```

`pose_id` 在 30Hz 层分配；`tick_seq` 在 200Hz 层分配；1kHz 层不携带任何帧身份。

---

## 为什么不在 200Hz 层直接接头

因为 200Hz 是**流式目标**，不是伺服。下游还有：

- Ruckig OTG（jerk / acc / vel 约束）把 200Hz 的阶梯整形成 1kHz 的 C² 轨迹
- 伺服位置环 → 电流环

如果把 200Hz 当作终点，会漏掉 OTG 引入的延迟与约束耦合，也会误判"指令到位"等于"末端到位"。

---

## 端到端延迟预算

| 环节 | 典型值 | 性质 |
|---|---|---|
| VR 采样保持 | 16.7ms（均值） | 不可消除 |
| 网络 | 5ms + 抖动 | 由固定延迟吸收 |
| **插值器固定延迟** | **33.3ms** | **主动引入** |
| QP IK | 0.5ms | 有界 |
| Ruckig OTG | ~3ms | 取决于 `j_max` 与目标变化率 |
| 伺服响应 | ~8ms | 厂商给定 |
| **合计** | **≈ 66ms** | |

主动引入的部分约占一半，换来的是速度连续与抖动隔离。要压延迟，优先提 VR 采样率，其次缩小固定延迟（下限是抖动峰峰值）。
