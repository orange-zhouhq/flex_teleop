## 控制框图

```
r(t) → S1 → 网络(τ,σ) → H → S2 → Σ → C_QP → ∫ → Ruckig → G_s → q(t)
       30Hz   抖动      重构器 200Hz  ↑   200Hz   1kHz    位置环
                                     └── FK(q_prev) ┘

q_fb ──▶ FK(q_fb) ──▶ T_actual      （观测支路，不闭合）
```

| 环节 | 传递特性 |
|---|---|
| `S1` | 30Hz 采样，`T1 = 33.3ms` |
| `H` | FOH 重构器，延迟 `T1`，频域 sinc² |
| `S2` | 200Hz 采样，`T2 = 5ms` |
| `C_QP` | 比例，`K = 0.5/step ≈ 22Hz` 等效带宽 |
| `∫` | 200Hz 离散累加 |
| `Ruckig` | 1kHz OTG，`v_max / a_max / j_max` 约束 |
| `G_s` | 伺服位置环，`f_bw ≈ 20Hz` |

级联：`C_QP（比例）→ ∫（累加）→ Ruckig（整形）→ G_s（一阶低通）`。

## 四个控制论特征

### ① 外环不闭合

`q_fb` 不参与目标生成，只做诊断。稳定性完全由内环（伺服）决定——插值器和 IK 怎么调整都不会让系统失稳，最坏只是跟踪变差。

这是本架构安全性的根源，也是相对双边遥操作最大的简化。

### ② 多速率 20:3 非整数

α 相位每 3 帧（40 个 tick）循环一次，不会均匀走 0→1。不能用 α 单调性做健康判据；任何数字滤波都会变成周期性时变系统。

→ 所以要用固定延迟，让相位可预测。

### ③ 三层语义转换

```
位置 r → 速度 dq（QP IK）→ 积分回 q_cmd → Ruckig 再整形一次
```

速度限幅 `dq_max` 与伺服带宽耦合：IK 若跑得比伺服能跟的速度快，领先量 `q_cmd − q_fb` 会单调增长。

→ `dq_max / a_max / j_max / f_bw` 必须一起标定。

### ④ 唯一可设计环节是 H

`S1 / S2 / τ / G_s` 都是给定的，只有重构器能调。延迟预算里那 33ms 是它的代价，抖动隔离也是它买的单。

## 真实状态观测

IK 的误差是**对 `q_prev` 自洽**的，不是对真实关节：

```
q_cmd[k] = q_cmd[k−1] + K · (r − FK(q_cmd[k−1]))
```

因此必须同时观测三个量：

| 量 | 定义 | 回答 |
|---|---|---|
| `e_model` | `r − FK(q_prev)` | 算法对不对 |
| `e_real` | `r − FK(q_fb)` | 系统到没到 |
| `Δq` | `q_cmd − q_fb` | 伺服跟不跟 |

关系：`e_real ≈ e_model + J · Δq`

负载过大、摩擦死区、末端被挡、限位拦截时，`e_model` 会持续为 0 而 `e_real` 很大——**这是本架构唯一"显示正常但实际异常"的口子**。

> **不要把 `q_fb` 引回 IK 做误差。** 那会闭合外环、引入伺服动态、可能振荡。正确做法是保持前馈生成，用 `e_real` 做监控与告警；若实测稳态误差确实大，再给 `q_prev` 加时间常数几百 ms 的慢积分补偿。

## 重构器选择

| 方案 | 等效延迟 | 速度连续性 | 抖动隔离 | 评价 |
|---|---|---|---|---|
| ZOH（保持最新帧） | `T1/2 ≈ 16.7ms` | 阶梯 | 差 | 靠伺服被动平滑 |
| **FOH（lerp/slerp + 固定延迟）** | **`T1 ≈ 33ms`** | 连续 | 好 | **推荐** |
| FOH 追赶式（α 钳 1） | 0~33ms | 周期性停顿 | 差 | 网络极好时可降级使用 |
| 外推/预测 | ≈0 | 连续 | 很差 | 高动态场景才值 |

例外：若伺服位置环带宽低于约 5Hz，ZOH 反而更优（阶跃被伺服吃掉，延迟少 16ms）。**先用实测确认伺服带宽再定。**

## 延迟预算

| 环节 | 典型 | 可控性 |
|---|---|---|
| VR 采样保持 | 16.7ms | 提采样率可降 |
| 网络 | 5ms + σ | 由固定延迟吸收 |
| 重构器 | 33.3ms | **主动引入，可调（下限=抖动峰峰值）** |
| QP IK | 0.5ms | 有界 |
| Ruckig OTG | ~3ms | 取决于 `j_max` |
| 伺服 | ~8ms | 厂商给定 |
| **合计** | **≈ 66ms** | 其中约一半是主动引入 |
